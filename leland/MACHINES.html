Lessons from the first run, all fixed 2026-11-03 evening:

  • WSL stops Linux a few seconds after the last connection closes, killing anything running (tested: a background heartbeat died within seconds). The first run only survived because the laptop kept a connection open. Fix: training is started by a Windows scheduled task, MicroduckTrain (runs as lelan, "whether logged on or not", highest privileges), which keeps Linux alive for the whole run. No laptop connection needed.
  • The automatic shutdown didn't happen (asking Windows from inside Linux failed silently). Fix: the task's Windows script shuts down from Windows itself: shutdown /s /t 300, 5 minutes after the run, enough for the laptop to fetch.
  • Copying results: the run is packed into C:\Users\lelan\microduck-runs\<name>.tgz, then fetched with scp.
  • Never send shutdown /a to "check": it cancels a pending shutdown.
  • rerun-gamer.local stopped resolving, so ssh pc uses 192.168.1.194. If the AT&T gateway ever gives the PC a different address, ssh pc breaks. Pin it with a reservation in the gateway (see below).

Training on the PC from the laptop: one command (working 2026-11-03)

leland/tools/pc-train start first-4000 4000 --resume first-750 model_749.pt   # wake, train, auto-off
leland/tools/pc-train status                 # how far it has got
leland/tools/pc-train wait first-4000        # wait for the end, then copy the result to ~/microduck-runs/pc/
leland/tools/pc-train wake | off             # switch the PC on or off by hand

Options: --keep-on (don't shut down afterwards), --power 130 (cap the graphics card at 130 W for less heat and noise; set back to 170 W after the run).

How it works:

  1. Wake: the laptop sends a Wake-on-LAN "magic packet" (to 50:eb:f6:ca:72:a1) and waits for SSH.
  2. Job: the laptop writes C:\Users\lelan\microduck-runs\job.env (name, rounds, resume, shutdown, power).
  3. Start: Start-ScheduledTask MicroduckTrain runs pc/pc-train.ps1 (Windows side: power limit, start Linux, shutdown), which runs pc/pc-run.sh in Linux (train, pack the result). Log, status and result go to C:\Users\lelan\microduck-runs\, so the laptop can check progress without touching Linux.
  4. Finish: result packed, power limit restored, PC shuts itself down 5 minutes later.

Tested end to end 2026-11-03: a 10-round job started by the task with nothing connected, power cap 170 → 130 → 170 W, result fetched, shut itself down at 21:31; later woken from the laptop: off 21:47:48, packet ~21:48:20, Windows up 21:48:43, SSH 21:49:02.

What it took to make remote switch-on work:

  • BIOS (Delete at the ROG logo, F7 Advanced): Advanced → APM Configuration → ErP Ready: Disabled, Power On By PCI-E: Enabled. Before that, the PC ignored wake packets from both the laptop and the wired Studio.
  • Windows: Fast Startup off (HiberbootEnabled = 0); network card already had Wake on Magic Packet and Shutdown Wake-On-LAN enabled.
  • The network port shows no lights when the PC is off, even though wake works. That's normal for this card.
