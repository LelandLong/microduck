What each piece is for

  • Rust: the language the duck's software (robotd, robotctl and the rest) is written in. cargo compiles it. rustup keeps Rust up to date (rustup update).

  • uv: installs Python and the Python libraries a project needs, kept inside that project (its .venv folder), so nothing clashes with my other Python installs.

  • microduck_rl: Pollen's training repo. The simulator uses it for:

    • duck-body, the physics model of the duck (MuJoCo) that the real software drives
    • the scenes (floors, rooms)
    • the ONNX Runtime library that runs the duck's neural-network policies on the Mac

    It's also where training happens, but that needs an NVIDIA GPU, so not on this Mac.

  • ~/microduck/target: the compiled duck software. Safe to delete with cargo clean; the next scripts/duck-sim rebuilds it.

  • ~/.cache/duck-sim: the running duck's logs, sockets, config, and the 10 official policies (alpha_walking.onnx, alpha_stand.onnx, roulade.onnx, …) downloaded from the Hugging Face Hub.

The Rust installer added one line, . "$HOME/.cargo/env", to ~/.zshenv, ~/.profile and ~/.bash_profile, so cargo and rustc work in every new Terminal window. Nothing else changed.

Using the simulator

From ~/microduck in Terminal:

scripts/duck-sim                    # start: MuJoCo window opens, duck stands up
scripts/duck-sim drive 0.4 0        # walk forward 8 s   ← give a speed! see below
scripts/duck-sim drive 0.4 0.5      # walk while turning
scripts/duck-sim drive 0 0.8        # turn on the spot
scripts/duck-sim ctl robot do roulade   # forward roll
scripts/duck-sim status             # is it healthy and standing?
scripts/duck-sim monitor            # live joints and sensors
scripts/duck-sim log                # the daemon's log (Ctrl-C to leave)
scripts/duck-sim down               # stop everything, close the window

In the MuJoCo window: drag to rotate the view, scroll to zoom.

⚠️ drive with no numbers does nothing visible

scripts/duck-sim drive defaults to speed 0.15, and today's walking policy treats anything below about 0.25 as "stand still". Measured 2026-11-03, 4 seconds at each speed:

speed distance
0.15 (default) 6 mm stands
0.20 8 mm stands
0.30 45 cm walks
0.50 82 cm walks

So always give a speed of 0.3 or more. (The script's default is probably older than the current policy; worth telling Pollen.)

How I checked it works (2026-11-03)

  • scripts/duck-sim started everything first time: duck stood up, control loop at 50.0 of 50 Hz.
  • Walking checked by measuring the duck's position in the simulation, not just asking it if it was OK (table above).

The simulated camera

Start the duck with its camera on:

scripts/duck-sim down
DUCK_SIM_CAMERAS=a scripts/duck-sim     # "duck-a can see — console at http://127.0.0.1:8080"

Then open http://127.0.0.1:8080 in a browser: the same console page a real robot serves, with the duck's camera view. Checked 2026-11-03: capturing at 32 fps (target 30), console page loads, and a frame grabbed from the camera socket shows the floor in front of the duck (images/duck-eye-2026-11-03.png).

GStreamer prints a screen of warnings (Python bindings, GTK 3 and GTK 4 both present). They are about pieces the duck doesn't use and can be ignored.

microduck-lab: training on the Mac

A community project (jonathanhawkins/microduck-lab), not Pollen's. It trains walking policies on the Mac's CPU with 32 simulated ducks instead of thousands on a GPU. It's for trying out reward ideas, not for producing a policy for the real robot. Its setup put its own pinned copies of Pollen's microduck and microduck_rl inside ~/microduck-lab, separate from mine.

From ~/microduck-lab/microduck_local:

uv run train-walk --envs 32 --steps 3_000_000 --run-name first-gait   # train
uv run eval-walk runs/first-gait/policy.onnx                          # test it
uv run duck-lab --world pitch          # the simulated room; then, in ../duck-viewer: npm run dev

My first training run (2026-11-03): 3 million steps took 9 minutes (the camera install was running at the same time). It learned to stand, rock-steady, but not to walk: 0 falls in the lab's test battery, yet 0.00 m moved when asked to walk. The whole story, with video: TRAINING.md. The policy is in ~/microduck-lab/microduck_local/runs/first-gait/policy.onnx.

Setup ran its self-tests: 56 passed, 1 skipped. A libc++abi … recursive_mutex crash message appeared as the test program exited, after the results; it didn't affect anything.
