# 2026-10-31: the road map (Claude Cloud, from the phone)

Asked for: a summary of what learning and creating policies looks like on the Mac and the PC once
everything is installed, in order, with ideas to try. Written from the repo docs
(`docs/robot/simulation.md`, `docs/robot/cheatsheet.md` "Policies and skills") and the Kevin Wood
notes. Nothing below has been run yet.

## Who does what
- **Mac = home base.** Read code, edit reward ideas, run the local simulator (`scripts/duck-sim`),
  watch results, quick CPU experiments (microduck-lab).
- **PC (RTX 3060, WSL2 Ubuntu) = training box.** Runs `microduck_rl` training for hours; you check
  in from the Mac.
- **HF Jobs = overflow** (L4 $0.80/h) when the PC is busy gaming.

## The loop, in order
1. **Play first (zero install):** browser simulator, Policy Playground, Arena.
2. **PC setup (once):** `wsl --install` → Ubuntu → NVIDIA driver already fine (596) → `nvidia-smi`
   inside WSL → install `uv` → clone `microduck_rl`.
3. **First training run, unchanged:** `uv run train Mjlab-Velocity-Flat-MicroDuck`, W&B option 3,
   cap with `--agent.max_iterations`. Walking ~750 iterations; better by ~4,000.
4. **Watch it:** `uv run play <task> --checkpoint-file logs/rsl_rl/.../model_750.pt`.
5. **Export to ONNX** (the file the duck loads), copy to the Mac.
6. **Mac simulator:** Rust + build this repo + `microduck_rl` venv → `scripts/duck-sim`. Load the
   policy into the real daemons: `ctl policy load walk <file>.onnx`; `ctl policy reset walk` undoes.
7. **Change one thing, retrain, compare.** Reward weights first.
8. **When the duck arrives:** same command on the robot (`sudo robotctl policy load walk ...`), on its
   stand the first time. Publish to the Hub if proud of it.

## Ideas to try, easiest first
- Same task, different iteration counts: see what "learning" looks like.
- Load community policies (`robotctl policy search microduck`, e.g. RemiFabre flamingo-cycle).
- Nudge a reward weight (e.g. prefer smoother steps) and compare gaits.
- A new skill (bow, wiggle, dance) like the community `polite-bow`.
- Prototype reward ideas on the Mac in microduck-lab, then train the winner on the PC.

## Making a "watch it learn" video (checked in the code, not yet run)
Checked in `microduck_rl` (cloned to a scratch folder) and mjlab 1.3.0 (the version its `uv.lock` pins).
- **Clips recorded during training:** `uv run train ... --video` (mjlab `train.py`). Writes short
  MP4s to `logs/rsl_rl/<task>/<date>/videos/train/`. `--video-length` (default 200 steps ≈ 4 s at
  50 Hz) and `--video-interval` (default 2000 *environment steps*, not iterations).
- **A clip of any checkpoint afterwards:** `play` / `scripts/export.py` take `--video`,
  `--video-length`, `--video-width`, `--video-height`, `--camera`. Run it once per checkpoint
  (`model_0/250/750/2000/4000.pt`); output goes to `.../videos/play/`.
- **Easiest and prettiest:** screen-record the live viewer (Windows `Win+Alt+R`, Mac
  `Cmd+Shift+5`) while you move the camera.
- Stitch in iMovie with a title card per stage. YouTube/family-friendly.
- Gotcha: the README mentions `scripts/render_policy.py`, but that file is not in the repo.
